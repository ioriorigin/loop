## 1. 判定基準（評価の前に固定した。H031-5ec の登録文と同一）

1. 各候補の手数料を**一次情報**（各サービスの公式ページ）から取り、1件あたりの粗利を出す
2. **必要人数 = 1,350,000 ÷ 粗利**
3. 必要人数に絶対の閾値は置けない（レビュー→販売の換算率を持っていない）。代わりに**順序**で判定する——
   **いまの本命（Kindle ¥1,650 / 35%、手取り ¥525、年 2,570 冊）より必要人数が1桁小さい候補だけを
   「別の形」として残す。** 1桁の改善が無い候補は、**既に届かないと分かっている形と同じ位置にいる**
4. 手数料の一次情報が取れなかった候補は「測れなかった」と書き、**粗利を推測で埋めない**

**閾値は 2,570 ÷ 10 = 257 人/年。** この数字は基準3から機械的に出る。評価の前に決まっている。

### 1.1 測れなかった手数料が、判定を止めなかった理由

note と Zenn の手数料は**取れなかった。** 2つの道具で試している（09-05 の教訓「外部の読み取りが
失敗したら、結論を書く前に別系統の道具を1つ試す」に従った）。

| 対象 | curl + ブラウザ UA | WebFetch |
|---|---|---|
| `help-note.com` の手数料ページ | **HTTP 403** | **HTTP 403** |
| `zenn.dev/faq` | 200。ただし**設問の見出しだけで、答えは JS 側**（「販売や振込の手数料は？」の文字列はあるが本文が無い） |200。同上（「記載なし」と返る） |

**それでも判定は出来る。手数料は必要人数を増やす方向にしか効かないからである。**
**手数料ゼロを仮定した必要人数が閾値を超えるなら、実際の手数料がいくらであっても超える。**
だから測れなかった候補には**下界**（＝最も有利な仮定）を置いた。表では `≥` で示す。

**推測値を置くのと下界を置くのは違う。** 推測は結論をどちらへも動かしうるが、
下界は**候補を落とす方向にしか使えない。** 落とせなかった候補については「測れていない」と書く。

### 3.1 表が言っている一番重いこと — **プラットフォームを変えても桁は変わらない**

候補 1・2・3 は、**売る場所を Kindle から note / BOOTH / Gumroad へ移した場合**である。
手数料は 35% から 5.6%〜10% へ、**6分の1 まで下がる。** それでも必要人数は 2,570 → 819〜909 で、
**3倍しか良くならない。閾値には1桁足りない。**

**理由は算術である。** 単価が同じなら、手数料をゼロにしても粗利は高々 ¥1,650 で、
**1,350,000 ÷ 1,650 = 819 人が下限になる。** 手数料の側にはもう削る余地が無い。

**「Kindle が悪いから届かない」のではない。「1件 ¥1,650 の単発販売」という形が届かない。**
出品先の議論（`ASKS.md` A-004b、Issue #11 の A-010）は、**この桁を1つも動かさない。**

### 3.2 単発のデジタル商品が閾値に届く価格を、逆算する

必要人数 257 人に届くには、**1人あたり 1,350,000 ÷ 257 = ¥5,253 の手取り**が要る。
BOOTH の 5.6% で逆算すると、**定価 ¥5,565。**

**棚の価格中央値は ¥600 である**（`MARKET.md` §7.1、実測15冊）。**その 9.3 倍。**

**この棚にその価格帯は無い。** よって——

> **単発のデジタル商品という形は、この棚が支える価格では、どの販売先を選んでも閾値に届かない。**

これは候補 1〜5 をまとめて落とす結論である。**販売先ではなく、取引の形が制約になっている。**

### 3.3 メンバーシップの必要人数には、この表が隠している仮定がある

候補 6・7 の「¥6,000/年」は、**12か月continueした場合の値である。**
**解約があれば、必要な新規獲得数はこれより多い。** 継続率を測る手段をいま持っていないので、
**225人・113人は「同時に抱えている必要のある会員数」であって、年間に集める人数ではない。**
数字を有利な側に読まないために書いておく。

## 4. 閾値を通った3つの形を、憲章の残り4軸に当てる

**必要人数（軸4）だけで決めない。** `CHARTER.md` §61 は5つの軸を置いている。
通った候補（6・7・8・9）を、残り4軸で採点する。

| 軸 | 月額メンバーシップ | 受託・請負 |
|---|---|---|
| **1. オーナーの継続工数がゼロに近いか** | **✗** 毎月の課金・解約・問い合わせが発生し続ける | **✗✗** 見積り・契約・納期の交渉・検収。**すべて人間が要る** |
| **2. 集客がプラットフォーム内で完結するか** | **△** note/Zenn/GitHub Sponsors には検索面があるが、Kindle ほど購買動線が太くない | **✗✗** 検索で見つかって発注が来る形ではない。**紹介と実績で決まる** |
| **3. 自分の出力が品質を決めるか** | **○** 書くもの・作るものが商品そのもの | **○** 同上 |
| **5. 在庫・原価・サポートの継続負担がゼロか** | **✗** 会員が居る限り、毎月出し続ける義務が生じる | **✗** 検収後の修正対応 |

### 4.1 これが、この文書で見つかった構造である

**軸4を通る形は、軸1を必ず破る。**

- 軸4 が要求するのは **1人あたり年 ¥5,253 以上の手取り**（§3.2）
- それを満たす形は3つしかない——**継続課金・受託・棚の中央値の 9.3 倍の単発品**
- **継続課金**は、毎月の課金と提供が続く。オーナーの継続工数は定義上ゼロにならない
- **受託**は、契約する人間が要る。同上
- **9.3 倍の単発品**は、§3.2 のとおり測定に支持されていない

∴ **軸1（オーナーの継続工数がゼロに近い）と軸4（単価 × 必要販売数が現実的）は、
いま測れている市場の上では同時に満たせない。**

### 4.2 憲章の評価枠は、この衝突を扱えない

`CHARTER.md` §61 は軸4をこう書いている。

> **4. 単価 × 必要販売数が現実的か** | 135 万円 ÷ 単価 = 必要販売数。
> **これが桁で無理なら、その候補は最初から落ちている**

**これは採点軸ではない。足切りである。** 「桁で無理なら落ちている」と自分で書いている。

そして `MARKET.md` §9 は 09-05 に、**本命に対してこの足切りを発動させた。**
どの組み合わせでも届かない、と。**発動したのに、候補は落ちなかった。**

**これは `MARKET.md` §11 で名指ししたのと、同じ型の欠陥である。**

| | 09-08 に見つけた欠陥（§11） | **本日見つけた欠陥（この文書）** |
|---|---|---|
| 条文 | §3.1「原稿を public に置かない」 | 軸4「桁で無理なら落ちている」 |
| 発動 | 置き場が未定のまま執筆回が来た | §9 が「どの組み合わせでも届かない」を確定させた |
| 起きたこと | 隣の §3.3 の語彙に上書きされた | **足切りが採点軸として読まれ、他の4軸の点で相殺された** |
| 共通 | **条件が満たされたのに、指示が適用されなかった** | **同じ** |

**Kindle が生き残った理由は、いま分かる。軸1・2・3・5 で最高点だったからである。**
**足切りを、4勝1敗の1敗として数えた。** 足切りは数えるものではない。**落とすものである。**

## 5. 決定（loop の工程。承認は要らない）

**候補を落とすのではなく、本命の役割を書き直す。** 理由は、憲章が既にそう書いていたからである。

`CHARTER.md` §266 は 09-04 の時点でこう書いていた。

> **したがって、第1弾は「135万円に届く商品」ではなく
> 「段階3（初回入金）に届くかを測る探針」である。**

**書いてあった。そして STATE も次の一手も、この本を目標への道として扱い続けた。**
§266 は §61 の軸4 と同じ経路をたどっている——**書かれ、発動し、適用されなかった。**

### 決定1: 本は探針である。目標への道ではない。**この語をこれ以降ずらさない**

`OUTLINE.md` §9.1 の「135 万円に要る冊数 2,570 冊/年」は、**達成計画ではなく、
この形では届かないことを示す数字として読む。** 本の仕事は「1円入るか」を測ることだけである。

### 決定2: 目標への道は、**オーナーの継続工数を要求する形しか無い**

§4.1 がそれを導いた。**この結論は、こちらの努力では動かせない。**
努力で動くのは軸3（品質）と軸4の分子（単価）だが、**単価は棚が決める**（§3.2 の 9.3 倍）。

### 決定3: 新しい商品を、いまこの回で作らない

**作れば「別の形を検討した」という体裁は整う。** それは制約ファイルが
「最も避けるべき振る舞い」と呼んだ**「やることがないので何か作る」**である。
§4.1 が示したのは**候補の不足ではなく、オーナーの時間という入力の不足**なので、
**入力を確かめる前に作るのは、確かめないための作業になる。**

### 決定4: オーナーへの問いを、**1つ差し替える**

Issue #11 は「原稿を private な置き場へ移すか、35% を受け入れるか」を聞いている。
**§3.1 が示したとおり、この問いはどちらに転んでも桁を動かさない。**
35% を 70% に変えても、必要冊数は **2,570 → 1,225 冊**（¥1,650 × 70% から同じ配信コスト
¥52.5 を引いた場合）で、**2.1 倍にしかならない。閾値には1桁足りない。**

> **併記。** `MARKET.md` §9 の 3,215 冊・1,770 冊は配信コストを引かない粗ロイヤリティで計算され、
> `OUTLINE.md` §9.1 の 2,570 冊は引いた値（¥525）で計算されている。**2つの表は換算の約束が違う。**
> ここでは 2,570 の側（引く）に揃えた。**揃えずに比べると、比が最大 5% ずれる。**
> 結論（1桁足りない）は動かないが、**動かないことを確かめてから揃えた。**

**上流の問いはこれである。**

> **135 万円に届く形は、いずれもあなたの継続的な作業時間を要求する。
> 月に何時間なら出せるか。その数字が、作る物を決める。**

- **0 時間 → 目標は現在の測定の上では達成不能である。** 本は探針として出して、
  初回入金までを見る。**目標そのものの見直しをお願いすることになる**
- **月 1〜2 時間 → 単発販売の積み上げ**（決済と出品だけ）。§3 の表では届かないが、探針は回る
- **月 5 時間以上 → メンバーシップが射程に入る**（候補6・7）。必要会員数 113〜225 人
- **不定期に商談が出来る → 受託が最も少ない人数で届く**（候補8・9、年 9〜27 件）

**14件の依頼のうち 12件が、この1つの答えの下流にある。**

## 6. この文書の限界（過大に読まれないように）

1. **必要人数は「売れる」を1件も含んでいない。** 分母の計算でしかない。
   225 人を集められるかは、**この文書は何も言っていない**
2. **手数料が測れた先は3つだけ**（KDP・BOOTH・Gumroad）。note・Zenn は下界で落としており、
   **落とせたのは「1桁の改善が無い」までであって、料率を知ったわけではない**
3. **継続率を測っていない**（§3.3）。メンバーシップの必要人数は同時在籍数であって、
   年間の獲得数ではない
4. **受託の単価 ¥50,000 / ¥150,000 は、一次情報から取っていない。** 置いた値である。
   **他の行と同じ資格で読んではいけない。** 一次情報で裏を取るまで、候補8・9 は
   「桁が違う可能性がある」以上のことを言っていない
   → **【2026-09-09 解消】§7 で裏を取った。** ココナラ 673 件の実測。棚の中央値は ¥10,000 で
   置き値は 84 パーセンタイル（典型ではない）。**だが目標に到達した 45 件の価格の中央値は
   ちょうど ¥50,000 だった。** 桁は違っていない。**§7.5 の限界5点を付けて読むこと**
5. **棚は Kindle の棚である。** メンバーシップや受託の「棚」は測っていない。
   §3.2 の 9.3 倍は単発デジタル商品についての制約であって、他の形の価格を否定していない

| 評価件数 中央値 | 1 件（**0 件が 284 件**） | 7 件 |

**置き値がどこに居たか。** ¥50,000 は下から **84.1 パーセンタイル**、¥150,000 は **94.1 パーセンタイル**。
**棚の典型ではない。** 「1件あたり ¥50,000」は、棚の中央値の **5倍**である。

| 単価 | 必要件数/年（手数料ゼロの下界） |
|---|---|
| 棚の中央値 ¥10,000 | **135 件**（月 11.2 件） |
| 75% ¥30,000 | 45 件 |
| 置き値 ¥50,000 | 27 件 |
| 置き値 ¥150,000 | 9 件 |

**置き値は「桁が違う」ほどは外れていなかった。だが典型でもなかった。**
棚の中央値で見ると必要件数は 27 → **135 件、5倍**である。

### 7.4 価格と件数を**同じ行の上で**掛ける — ここが本題

§6 の限界1 は「**必要人数は『売れる』を1件も含んでいない。分母の計算でしかない**」と書いた。
この棚では、それを埋められる。**評価件数が、その出品が実際に積んだ取引数の下界だからである。**

**別々に見ると、両方とも届いて見える。** 必要件数 27 件/年 を生涯で超えた出品は 17.4%、
9 件/年 なら 26.3% ある。**だが、高い出品とよく売れる出品が同じ出品だとは限らない。**
だから同じ行の上で掛ける。**価格 × 評価件数 = その出品が生涯に積んだ売上の下界。**

| 生涯売上（下界） | 該当する出品 |
|---|---|
| **≥ ¥1,350,000（目標の1年分）** | **45 / 673 件（6.7%）** |
| ≥ ¥675,000（半分） | 81 件（12.0%） |
| ≥ ¥135,000（1/10） | 168 件（25.0%） |
| 中央値 | **¥8,000** |
| 75% / 90% / 最大 | ¥129,000 / ¥910,000 / ¥18,000,000 |

**これが、この文書で初めて出てきた「目標が分布の内側にある棚」である。**
Kindle の棚では、閾値に届く単価が中央値の **9.3 倍**で、そんな価格帯の本は棚に1冊も無かった（§3.2）。
ここでは、**目標の1年分を生涯で積んだ出品が 15 件に1件ある。**

**そして置き値 ¥50,000 は、外れてはいなかった。**
生涯 ¥1,350,000 を超えた 45 件の**価格の中央値が、ちょうど ¥50,000** である
（最小 ¥3,000 / 最大 ¥500,000、評価件数の中央値 90 件）。
**棚全体の典型としては 5 倍高すぎたが、目標に到達した集団の典型としては当たっていた。**
置き値が当たっていたことと、置き値に根拠があったことは別である。**いま初めて根拠が付いた。**

### 7.5 この節が言っていないこと（数字を強く読まないために）

1. **生涯であって、年ではない。** 45 件が何年かけて積んだかは測れていない（出品日が取れない）。
   目標は**年** 135 万円である。評価件数の中央値 90 件を年 27 件のペースで割ると **3.3 年**になる。
   **この棚の「到達した集団」でさえ、目標のペースの 1/3 で走っている可能性がある**
2. **検索結果は人気順に近い。** 上位に成功した出品が集まる。**6.7% は母集団の率の過大評価である**
3. **評価件数 ≤ 取引数**（書かない購入者がいる）で、**表示価格 ≤ 実際の受注額**（最低プランの価格）。
   この2つは**逆向き**に効く。生涯売上の下界は、両方の意味で下界である
4. **§4 の結論は動かない。** 受託は憲章の軸1（オーナーの継続工数がゼロ）を**最も強く破る形**である。
   単価に根拠が付いたことは、**実行できることを意味しない。** A-012 の回答が要る
5. **仮説を登録していない。** 測ってから仮説の形に書き直すのは H009 で自分を疑った振る舞いそのものである。
   **予測を先に置いていないので、`hypo` には積まない。** 測定として記録する

### 7.6 §6 の限界4 は、これで閉じた

限界4 は「一次情報で裏を取るまで、候補8・9 は『桁が違う可能性がある』以上のことを言っていない」だった。
**裏を取った。桁は違っていない。** §3 の表の候補8・9 は、他の行と同じ資格で読んでよい。
**ただし §7.5 の5点を付けて読む。**
