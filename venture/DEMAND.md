### 3.1 自前の試し撃ちでは需要を測れない — 他人の売れ方で測る

**loop のアカウントは読者 0 人である。** そこで何を試しても、結果は 0 に近くなる。

loop は 6〜12 時間ごとに無人で起き、読み、書き、push する。**これは本の執筆より、継続課金と噛み合う。**

どちらも「定期的に無人で動く」ことが原価になる。

**これは候補を決める根拠ではない。G1〜G4 を通った候補が複数あったときの、順位付けの材料である。**

### 8.3 違いの1行（手順1）

> **単機能の「Blender不要」ツールは1種類の改変しかできない。Synaptic は何でも頼めるが、Blender を入れて開いて見ている必要がある。
> これは、何でも日本語で頼めて、Blender を入れも開きもしない——ファイルを渡すと、直したファイルと前後の比較画像が返ってくる。**

**この1行が本当であることを、このコンテナで確かめた（2026-09-25 12:5x UTC）。**

先行品は 450 人以上の Discord でサポートしている。**こちらはオーナー月 5 時間（A-012）なので、サポートの経路を作らない。その代わりに、問い合わせが生まれる原因を設計で潰す。**

| 問い合わせの原因 | 潰し方 |
|---|---|
| **インストールできない** | **`uv` 1本で入る形にする**（Python の版を `uv` が自動で取ってくる。`bpy` は Python 3.11 限定なので、ここを利用者に触らせない）。**Windows / macOS での導入は GitHub Actions の実機ランナーで毎回検証する**——loop は Windows を持たないが、CI は持っている |
| **動かない理由が分からない** | **`doctor` コマンド**を付ける。Python・`bpy`・AI クライアント設定・書き込み権限を順に調べ、**失敗ごとに日本語で「次に何をするか」を1行出す**。各エラーに番号を振り、同梱のトラブルシュート表の行と1対1にする |
| **改変で元のアバターが壊れた** | **元のファイルは絶対に上書きしない。** 出力は必ず別名＋前後の比較画像。**失敗しても失うものが無いので、相談する理由が生まれない** |
| **何が出来て何が出来ないか分からない** | 販売ページと同梱文書に**「出来ないこと」を先に書く**（VRM・Unity 側の設定・PhysBone など）。出来ることは、**検証済みの改変レシピの一覧**として出す（レシピごとに前後画像の実例つき） |
| **AI が変な改変をした** | 改変は**レシピ（検証済みの bpy 手順）を AI が選んで引数を埋める**形を既定にする。自由記述の bpy 実行は「上級」として分け、比較画像で利用者が採否を決める |

**販売ページに「個別サポートはありません」と明記する。** 問い合わせは BOOTH のメッセージでオーナーに届くので、ゼロには出来ない。
**ゼロに出来ない分は、届いた問い合わせを表の新しい行にして次の版で潰す**（loop が 6〜12 時間ごとに回る強みは、ここで使う）。
