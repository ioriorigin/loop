## 1. 分量をこう置いた理由

Kindle のリフロー型にページ数という固有の量は無く、KDP が計算する「Kindle 換算ページ数」で表示される。
**日本語の技術書で 48,000 字は、おおよそ 130〜170 ページ相当に落ちる。**
（換算の係数は KDP が持っており、こちらから確定できない。**出品時に実測して、この行を訂正すること。**）

なぜこの帯にしたか。上下の両方に理由がある。

- **下限。** ¥1,200 という価格に対して、2万字台は「短い」と読まれる。
  Kindle の技術書は返品期限内の返本が容易で、**分量不足は返本という形で直接ロイヤリティを削る。**
- **上限。** 6万字を超えると、この題材では**実運用ログの引き写しで水増しする誘惑**が出る。
  `.claude/rules/autonomous-loop.md` が「やることがないので何か作る」を最も質の悪い失敗と呼んだのと
  同じ形が、原稿でも起きる。**引用は、主張を支えるぶんだけ載せる。**

**1章あたり 4,000〜7,000 字**を目安にする。12時間ごとに1回走る自分にとって、
**1回の稼働で1章の初稿が書ける単位**であることを優先した。
章が回をまたぐと、途中で死んだ回の書きかけが宙に浮く。`round open` を作業の前に置いたのと同じ設計思想である。

### 章の並びをこうした理由

**「作り方 → 壊れ方 → 縛り方 → 失敗史 → 再現」の順にした。**

素直な並びは、失敗史（7章）を最初に置くことである。物語として強い。
**それをやらなかったのは、失敗史が「何を作ろうとしていたか」を知らない読者には意味を持たないからである。**
`sources` が無くて clone できなかった話は、`sources` が何かを知らなければただの障害報告になる。

逆に、6章（規則）を5章（計器）の後ろに置いたのは順序が効く。
**停止条件は、参照する量が先に無ければ書けない。** これは本書の主張そのものなので、
章の並び自体が主張を体現している形にした。

## 4. 執筆順序 — 章番号順には書かない

| 順 | 章 | なぜこの順か |
|---|---|---|
| 1 | **まえがき** | 誰に何を渡す本かを先に固定する。ここがぶれると全章がぶれる |
| 2 | **第1章** | 問題設定。ここまでで「読者が最初の3分で読む部分」が揃う |
| 3 | **第5章** | **本書で最も他に無い章。** ここが弱ければ企画ごと見直す。先に書いて確かめる |
| 4 | 第2章 → 第3章 → 第4章 | 実装の説明。順に積む |
| 5 | 第6章 → 第7章 | 規則と失敗史 |
| 6 | 第8章 → 付録 → あとがき | 再現手順は、他の全章が確定してから畳む |

**第5章を3番目に置いたのが、この順序の要点である。**
売り物の価値は「実運用の計器の話」に集中していて、そこが書けなければ他が揃っても売れない。
**弱い可能性のある部分を最後に回すと、引き返せなくなってから分かる。**
`CHARTER.md` §8 が第1弾を「探針」と位置づけたのと同じ理由で、**探るなら早く探る。**

1. **コード例が全て実行済みであること。** 実行した回の日付を原稿の脚注に残す

## 8. H029-036（refuted）の反映 — 2026-09-06

**反映は3件。§3 の章立てと §1 の分量は変えない。** 変える理由が観測から出ていないからである。

### 8.1 本書を「第1巻」として出す。ただし**分割しない**

**素直な反映は「47,500 字を2巻に割る」である。それはやらない。**
割ると1巻あたり 24,000 字前後になり、§1 で「¥1,200 に対して 2万字台は短いと読まれ、
**分量不足は返本という形で直接ロイヤリティを削る**」と書いた帯を、自分から下回る。
棚のページ数中央値は 169 頁（`MARKET.md` §7.1）で、本書の 47,500 字（130〜150 頁）が既にやや下である。

**だから「巻として出す」は、分割ではなく予告で満たす。**

- 本書を **シリーズ第1巻**として位置づけ、**あとがきと紹介文に第2巻の主題を明記する**
- **第2巻の主題は「収益目標を渡された自律エージェントが、外部への出口を持たないまま何をしたか」。**
  `venture/` 一式（憲章・工程の切り分け・`ASKS.md`・市場調査・この判定そのもの）が一次資料になる。
  **本書と同じ性質——loop しか持っていない記録——を満たす主題は、いまこれ1本しか無い**
- **第2巻を書く確約はここではしない。** 予告は「シリーズである」ことの表明であって、
  刊行の約束ではない。**書けないまま予告だけ残すのは §6-4（失敗を薄めない）に反する**ので、
  第1巻の売上が 0 のまま第2巻に進むかどうかは、その時点の台帳（`LEDGER.md`）を見て決める

### 8.2 章の型を、第5章が踏んだ形に固定する

上位2件に共通していた「物語形式」は、**本書では既に素材として持っている**（`MARKET.md` §10.3）。
主人公は loop、時系列は実在の日付、失敗は実際に起きたものである。
**足りないのは素材ではなく、型が章ごとに揺れていることのほうである。**

第5章が踏んだ形を、全章の既定にする。

1. **起きた事実を、日付つきで先に置く。** 説明から始めない
2. **そのとき何を誤って読んだかを書く。** 正解の前に、誤読を書く
3. **どう直したかを、実物（コミット・スクリプト・出力）で示す**
4. **最後に一般化する。** 一般化を先頭に置かない

**これは物語の飾りではない。** §6-4 が「本書の差別化は、成功例ではなく失敗の粒度にある」と
書いたことの、章単位での実装である。**2 を飛ばした章は、ただの手順書になる。**

  2. **シリーズ第1巻であることの明示**（§8.1）

#### 決定 — TARGET_CHARS は動かさない。残りの計画を削る
