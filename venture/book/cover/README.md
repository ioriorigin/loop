## オーナーの工程は1つだけになった

A-008 はもともと「表紙をどう用意するか」を3つ並べてオーナーに問う形だった。
**その問いは、もう問う必要がない。**

- **やること:** KDP の出品画面で `cover.jpg` を選ぶ。**それだけである**
- **その前に決めること:** 著者名義（A-011）。決まったら上の1コマンドで組み直す

## 検査している項目（KDP の要件）

`build_cover.js` が書き出した直後に、**ファイルの中身から**測る。

| 項目 | 値 |
|---|---|
| 形式 | JPEG（KDP は JPEG / TIFF のみ） |
| サイズ | 1600 x 2560 px（KDP の推奨値） |
| 縦横比 | 1.6 : 1 |
| 長辺 | 1000 px 以上 |
| 容量 | 50 MB 未満 |
| 版のはみ出し | 無し（題が切れていないか） |
| 著者名義 | 埋まっているか（未指定なら校正用と表示して止める） |

**書き出した側の自己申告ではなく、JPEG の SOF マーカーから実寸を読んでいる。**
「確認と称して別のものを測る」形にしないため（2026-09-04 に自分で書いた）。

## 版の意図

- **題を最優先にした。** KDP の検索結果では表紙は幅 160px 前後まで縮む。
  実際に 160px へ縮めて確認し、**題の2行だけは読める**ことを見た（副題・シリーズは読めない。これは想定内）
- **下端の図は本文の主張そのものである。** 器（コンテナ）が右へ行くほど薄く消えていき、
  その下を1本の線（git に置いた記憶）が途切れずに貫いている
- 書体は **IPAPGothic**（この環境にある唯一のまともな日本語書体。明朝は入っていない）

## 組み直すときの注意

- `cover.html` の `1600px / 2560px` と `build_cover.js` の `W / H` は**対になっている。**
  片方だけ変えると検査が落ちる（落ちるように作ってある）
- JPEG で書き出せる手段は、この環境ではこれ1つである。
  `chromium --headless --screenshot` は PNG しか吐かず、同梱の ffmpeg は
  `--disable-everything` ビルドで JPEG encoder を持たない。PIL も cairosvg も入っていない
