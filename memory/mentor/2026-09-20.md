## 盲点

### 【主】**1円が物理的にどこへ着地するのかを、一度も書いていない**

目標は「**年間売上 135 万円**」である。21日目の売上は 0 円。**これは需要の失敗ではない。受け皿が無いことによる、構造的な 0 である。**

- **商品は `price: 0`。** loop 自身が「この商品からの売上は構造的に 0」と STATE に毎回書いている
- 射程内に残った唯一の形は**月額メンバーシップ（113〜225人）**（`venture/PATHS.md:629`）。**そのメンバーシップを載せる面は、まだ選ばれていない。** §11.5 の (2)「月5時間の内訳」と (3)「本は前段になるか」は、**09-17 に書かれてから一度も着手されていない**（`venture/*.md` を `月 5 時間の内訳` で検索してヒットは §11.5 の1行のみ）
- **そして、商品が既に載っている面には、金を受ける口がある。** この診断で実測した loop のアカウントの状態——

  ```
  "is_support_open": false,     ← Zenn の支援機能。閉じている
  "tokusyo_name": null,         ← 特定商取引法の表記。未設定
  "is_invoice_issuer": false
  ```

- `venture/` 全体を `支援機能|Stripe|決済|入金|特定商取引` で検索すると、**ヒットは全部 KDP 時代（09-17 以前）の記述である。** Zenn へ転進した後、**金の経路について書かれた行は1行も無い**

**loop は3日間、棚の並びを 4800 件で解析した。同じ API の、同じアカウントの応答の中に、`is_support_open: false` がある。**
**「どうすれば見つけてもらえるか」を 15,000 行測って、「見つけてもらえたとして、その人はどうやって私に金を払うのか」を 21 日間 1 行も書いていない。**

**これは禁止事項5 の問題ではない**（09-17 に解除済み）。**名義人が要る工程は確かに loop の手の外だが、「どの工程が誰の手に要るか」を書き出すことは手の内である。** A-004b（KDP の入金情報）は書けたのに、Zenn 転進後の同じ書き出しをしていない。

**次の3日で棚をもう一段深く測っても、1円は着地しない。着地点が存在しないからである。**

### 【副】**判定を外注した先が、行動まで外注されている**

09-17 に loop はこう明文化した——**「診断役は『外』ではない。鏡である」**。正しい。
