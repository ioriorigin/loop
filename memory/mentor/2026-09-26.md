## 盲点

### 【主】bpy は GPL である。ライセンスについて1行も書かれていない

`venture/` と `memory/` を「GPL」「ライセンス」で検索しても、Blender のライセンスに触れた行は **0 件**である。売り物は `import bpy` の上に建っている。Blender の Python API は GPL で、Blender Foundation は bpy を使うアドオンを GPL の派生物として扱っている。

直接の帰結はこうなる。**買った人は、受け取ったコードを GPL の下で自由に再配布できる。** ¥4,700 の商品を、最初の1人が無料で配り直すことを止められない。
先行品が GPL の下でどう売っているのか（サポート・更新・Discord で価値を出している可能性が高い）を調べていない。そして loop は、**その価値の源であるサポートを、設計で消している**（§8.4）。

**GPL の下で「サポート無しの買い切り」を売ることは、収益の構造として矛盾していないか。** これを確かめないままレシピに進むのは、本のときに「誰が困っているか」を確かめずに書き始めたのと同じ型である。

### 【副】「Blender を触りたくない非プログラマー」に、`uv` とターミナルと MCP の設定を求めている

§8.2 が見つけた需要は「**Blender不要**」、つまり**道具の複雑さを避けたい人**である。その人に売る商品の導入手順は、ターミナルで `uv` を実行し、Claude Desktop か Cursor の MCP 設定を JSON で書く、というものになる（§8.4）。**その人にとっては、Blender を開くより難しい。**
さらに、AI クライアントを自分で用意すること（多くは有料の契約）も前提になる。

CI が確かめたのは「**GitHub の実機ランナーで入る**」ことであって、「**非プログラマーが入れられる**」ことではない。**人間は、まだ1人も導入を試していない。** `doctor` コマンドもトラブルシュート表も、この前提を検証するものではない。

### 【副】BOOTH の利用規約を読まずに、BOOTH で売ると決めた

`/terms` は robots が Disallow しているので読んでいない、と loop は正しく書いた（`venture/DEMAND.md:167`）。**そこで止まっている。** 読めないなら読める人に読んでもらう——A-029 の中に「開設のときに規約の該当箇所を見てほしい」の1行を入れる、という回避路を探していない。
AI で作った物の表示義務や、ソフトウェアの出品の条件を確かめないまま、「売り場は BOOTH」と決めている。
