## この回で潰した欠陥 — 「見えるようになった」と「数えられるようになった」の距離を詰めた

**`round orphans` は 09-03 から検出できていたが、一度も数えられていなかった。**
台帳に行が無い回なので、密度の遡りが数える対象そのものを持たなかった。
**規則にその限界を自分で書いて残したまま、4日そのままだった**（STATE の次の一手に2回連続で載っていた）。

`orphans` に機械向け出力（`orphans 7 3600 epochs`）を足し、`gaps` が台帳の行と同じ列に並べる。
根拠は「締めを飛ばした回を薄い回と数える」のと同じで、**濃かった証拠を1つも申告せずに終わった回**である。
判定を通りにくくする方向にしか働かないので厳格化にあたる（オーナーの承認は要らない）。

実装で気をつけた2点。**(1) commit ではなく「回」の単位で数える**——commit 1件を1回と数えると
**よく働いた回ほど薄い回として重く数えられる**、意味が逆さまの計器になる（近接 commit を2時間で畳む）。
**(2)「締めを飛ばした回」とは別の行で出す**——直し方の違う2つを1つの数に潰さない。

回帰テストは `bin/selftest` **Q 節（7件）**。**変異テストで検出力を確認済み**——
列に混ぜない変異でちょうど2件、畳まない変異で1件が落ちる。**selftest 132 → 139。**

### 実装中に、この変更自身が新しい欠陥を作った（塞いだ）

`gaps` の awk に入力を1つ足したら、**`NR == FNR` の慣用句が「1つ目の入力が空」で壊れた。**
1レコードも読まれないので、**2つ目の1行目が NR==FNR==1 で1つ目と誤認され、黙って捨てられる。**
selftest の J / L / O 節が 10 件落ちて分かった。
**台帳を書かなかった回が0件なのは通常の状態であり、その通常の状態でだけ壊れる計器だった。**
停止条件を強くするための変更が、**停止条件そのものを毎回黙らせる形で入りかけた。**
