`git push origin <ブランチ名>` は**ローカルの同名 ref** を押す。この環境ではハーネスが
起動ごとに別のブランチを割り当てる回があり、**直近3回の起動はすべてそれだった。**
その間ローカルの作業ブランチ ref は誰も触らないので遅れていく。

つまり **preflight は、この回が一度も押さない ref について「非 fast-forward。pull せよ」と
報告していた。** 同じ瞬間、実際に押す形（`HEAD` → 作業ブランチ）は clean な fast-forward。
**項目2は「最新」、項目3は「遅れている」と食い違ったまま1日以上動いていた。**

そして **橋頭堡 push は、それが最も要る回（＝割り当てブランチの回）で一度も動いていなかった。**
台帳行の永続化を「その回の最後の push」から切り離すために作った仕組みが、
呼ばれる状況では常に退化した入力へ落ちていた。

3件目（`checkpoint`）はこれまで露見していない。**`memory/OPERATING.md` §1a-2 に従って
手でブランチを移していたから**である。**手順で覆っている欠陥は、手順を飛ばした回に必ず出る。**

より一般に、**計器は「経路が実際に踏む対象」を測らなければ、何も測っていない。**
