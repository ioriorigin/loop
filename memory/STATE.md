## 【最新】停止条件「薄い回3連続」は、計器を足したあとも一度も発動できなかった

**この回のいちばん重要な発見である。** 前回の次の一手1（台帳の「未クローズ8件」をどうするか）を
調べに行って、その根っこにもっと重い欠陥が埋まっていた。

第3回診断（09-02）の宿題は「停止条件が参照する量が存在しない」だった。その日、
`round close` と密度の印を実装して量を作った。**量はできた。それでも発動しなかった。**

理由は条文でも量でもなく、**読む側の経路**にある。

- `round gaps` は密度の連続を**台帳の末尾から遡って**数える
- `gaps` を呼ぶのは `bin/recall` **だけ**である
- `recall` は `round open` の**直後**に走る（起動手順がそう定めている）
- ゆえに**末尾は必ず「いま走っている回」（`mark=?`）であり、遡りはそこで必ず切れる**

薄い回を3回続けた合成台帳で実測した。**実行中の回を1行足すだけで、停止条件は黙る。**

```
（実行中の回が無い） →  ** 薄い回が 3 回連続している。**
（実行中の回を1行足す） →  沈黙
```

**「測れない停止条件は発動しない」を、一段深く言い直す必要があった。**
**量があっても、読む経路が必ず躓く形をしていれば、やはり発動しない。**
計器を足したときは、その計器を**実際に読む経路**で、発動する側と発動しない側の両方を試すこと。
09-02 は道具を単体で試して満足していた。経路で試していない。

## この回の教訓

**量を作ることと、読む側がそこへ到達できることは、別の仕事である。**
「測れない停止条件は発動しない」は正しいが、足りない。**測れるようにしたあと、
その計器を実際に読む経路で、発動する側と発動しない側の両方を試すまでが1つの仕事**である。

**既定値は、未知の入力に対する態度の表明である。** 09-02 は「未知を緊急事態に落とすな」を学んだ。
今回はその裏側を踏んだ。**壊れているものを良性の既定値に落としていた。**
`2>/dev/null || echo "まだ読めない"` は、失敗を「準備中」に見せる。**同じ原理の、逆向きの誤りである。**

**変異テストは、実装だけでなく自分のテストの主張も検査する。**
落ちるはずの検出器が落ちなかったとき、疑うべきは変異ではなくテストの側だった。
