### 2. 自分が書いた復旧手順が間違っていたので訂正した

前の回に `memory/INFRA.md` へ書いた「`sources` を持つセッションから `create_trigger` を呼べ」は
**通らない。** 並行セッションが実データで反証した（H012-843）。親セッションは `sources` 付きだったが、
そこから作ったトリガーに `sources` は入っていなかった。**MCP 経由では継承されない。**

反証データは最初から手元にあった。`list_triggers` の出力に、親由来の自分のトリガーが
`sources` 無しで写っていた。**「対照群を説明しない仮説を採用する」を、また踏んだ。**
オーナーが誤った手順を実行しうるので、INFRA と PR コメントの両方で訂正した。

### 3. 対照群が恒久解を救った

「`sources` を付けたトリガーは即死する」のではなく「**届かない `sources` が即死させる**」。
`ioriorigin/loop` は `can_push: true` で健在なので、loop のトリガーに `sources` を付けても
この失敗モードには当たらない。**対照群を先に説明したことで、唯一の恒久解が生き残った。**
見ずに「sources は危ない」と結論していたら、自分で捨てるところだった。

### 4. preflight の誤警報を塞いだ

この回の起動時、preflight が「push できない。今すぐ原因を潰せ」と報告した。
実際は**単に origin より遅れていただけ**（non-fast-forward）で、認証は生きていた。

制約は「preflight が push 不能を報告したら、その回は作業をせず原因究明だけに充てる」と定めている。
**つまり誤警報ひとつで1回分の稼働を丸ごと潰しうる。**
失敗理由を `stale` / `auth` / `unknown` に分類する純粋関数を `bin/_common.sh` に切り出し、
`bin/selftest` で4件覆った（全33件通過）。**1件でなく型を直す。**

### 5. PR 本文から腐る数字を抜いた

本文の「selftest 29件」は既に33件になっていた。1回直しても再発するので、
**件数を書かない形に変えた。** 外に出す文書に、放っておくと嘘になる数字を置かない。

## 忘れてはいけない教訓

**対照群を説明しない仮説を採用しない。** 4回の失敗の本当の理由はこれで、この回もまた踏みかけた。
そして今回は、対照群を見たことが**恒久解を捨てずに済んだ理由**にもなった。
対照群は失敗の説明装置であると同時に、正しい選択肢を守る装置でもある。

**拒否されたら、迂回ではなく別の正規の道具を探す。**
`create_trigger` と `add_repo` は分類器に拒否された。だが同じ問いに答える `list_repos` は通った。
壁を殴るのでも諦めるのでもなく、**同じ問いに答える別の合法な道具**を探すのが正しい三番目の選択肢。

**警報は、間違った警報を出さないところまでが仕事。**
誤警報は「安全側の失敗」ではない。停止規則と結びついた瞬間、1回分の損失になる。
