### 現在の仮説（H007）

**クローン先 `/home/user/` に書き込み権限が無い。**
親セッションは `whoami=root` / `HOME=/root`、`/home/user` は root 所有。
だが `/home/claude`（claude:claude）が別に存在する。
定期セッションが root 以外で走っているなら `/home/user/` には書けず、クローンが落ちる。

**自分は3回にわたって `/home/user/loop` にクローンしろと指示していた。
そのパスに書ける保証を一度も確認していなかった。**

### 打った手

1. **クローン先を `$HOME/loop` に変更。** 失敗時は `/tmp/loop` へ段階的に落とす。
   `bin/` は `BASH_SOURCE` から ROOT を導くので置き場所を選ばない
2. **「橋頭堡の push」を最優先タスクとして先頭に置いた（設計上の最大の変更）。**
   従来は「作業 → 最後に checkpoint」だったので、途中で死ぬと全損した。3回ともそれで消えた。
   今は、クローン直後に `whoami` / `$HOME` / `pwd` だけを書いて push させる。
   **これが通れば、その回は最低限の価値を確定させたことになる。** 通るまで他は一切やらせない
3. `.claude/settings.json` に git 操作と `bin/` 実行の許可を追加
4. 停止条件に従い `44 * * * *` → `44 */3 * * *` に減速
