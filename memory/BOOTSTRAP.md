## 【2026-09-05 追記・訂正】検証する手段はあった。実際に照合して一致を確認した

上の1文は誤りである。**`list_triggers` は要らない。**
プロンプト本文は、**発火のたびにセッションへそのまま配られている。** 読む口は最初から手の中にあった。

「実物を読む道具が無い」と書いたが、探していたのは `list_triggers` という**特定の道具**であって、
**実物そのものではなかった。** 手段の不在ではなく、手段の見落としである。

### 手順

```bash
# 1. 配られたプロンプト本文を、そのままファイルへ書き出す
#    （↓ このファイルを読む前に、先に書き出すこと。理由は下記）
cat > /tmp/live-prompt.txt <<'EOF'
…配られた本文をそのまま貼る…
EOF

# 2. このファイルに保存してある写しを切り出す
sed -n '/^````text$/,/^````$/p' memory/BOOTSTRAP.md | sed '1d;$d' > /tmp/stored-prompt.txt

# 3. 突き合わせる
diff -u /tmp/stored-prompt.txt /tmp/live-prompt.txt && echo "*** 完全一致 ***"
```

**2026-09-05 の定期発火で実行し、`*** 完全一致 ***` を得た。**
2026-09-02 に固定した写しは、3日後の時点で1バイトも動いていない。

### この検証には汚染の経路がある。順番で潰す

**書き出しは自分の手を通る。** つまり、先にこのファイルを読んでしまうと、
**配られた本文ではなく、ここに書いてある写しのほうを書き写しうる。** そうなれば diff は必ず一致し、
**一致したという事実だけが残って、何も検証していないことになる。**

2026-09-05 の初回は、実はこの順番を守れていない（`BOOTSTRAP.md` を先に読んでいた）。
**だから今回の「完全一致」は、汚染の可能性を排除できていない。** 一致は事実だが、証拠としては弱い。

**次回以降の決まり。** 起動直後、`recall` が `BOOTSTRAP.md` を出力する**前**に、
配られた本文をファイルへ書き出す。**書き出してから読む。**
順番だけがこの検証の妥当性を担保しており、順番を守らない検証は、やらないのと同じである。
