## 外したこと

**フックは上流の設定を一切読まない。** 実物（`~/.claude/stop-hook-git-check.sh`）はこうである。

    if git rev-parse "origin/$current_branch" >/dev/null 2>&1; then
      upstream="origin/$current_branch"

**名前を組み立てて `rev-parse` するだけで、`branch.<name>.merge` を見ていない。**
だから上流を設定しても件数は動かない。実際、設定した直後の締めで**同じ報告が出た（5件 → 7件）。**

## 本当の原因 — 中身の無い remote-tracking ref

| 測ったこと | 値 |
|---|---|
| `git rev-parse origin/claude/jolly-ride-1gc1k3` | **解決する。** `3059bb9`（起動時点の `main`） |
| `git ls-remote --heads origin claude/jolly-ride-1gc1k3` | **空。origin にそのブランチは存在しない** |
| `origin/claude/jolly-ride-1gc1k3..HEAD` | **7** |

**ハーネスは起動時に remote-tracking ref だけを作る。実体のブランチは origin に無い。**
その ref は起動時点の `main` に固定されたまま動かないので、
**この回が打った commit は全部その先に積まれ、全部「未 push」に見える。**

解いたのは、割り当てブランチを**実際に origin へ押した**こと。
押し先の変更ではない——`venture-135` にも `main` にも同じ commit が既にある**重複**である。
だから `round gaps` が読む場所から記録が外れる心配は無い。
