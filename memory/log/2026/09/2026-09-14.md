## 見つけたもの

原稿（`venture/book/manuscript/`）の脚注が、**再現できないコミット数を4件載せていた。**

| 章 | 載っていた値 | 実測（完全なクローン） |

| 第3章 | 109 | **139** |

**まえがきは自分でこう書いている**——「本書の記述が正しいかどうかは、読者が自分で確かめられる。
public である。**本文がリポジトリと食い違っていたら、リポジトリのほうが正しい。**」
**検算を勧めておいて、その検算が4か所で合わなかった。**

## 原因 — 書いた回の不注意ではない。道具の既定値である

**定期発火のコンテナのクローンは浅い。** `git rev-parse --is-shallow-repository` が `true`。
`git rev-list --count` は**接ぎ木の境界で黙って止まる。エラーも警告も出ない。**
`git log --reverse main | head` は `Initial commit`（08-30 08:24）を返すので、
**履歴が完全であるように見える。** unshallow したら main の累計が **195 → 243**。48 件、約 20% が欠けていた。

## この回、自分も同じ穴に落ちかけた

**最初の修正案は 78 → 56 だった。** それも浅いクローンで測った値である。
「本文の数値は多すぎる」と結論して、より少ない数へ直そうとしていた。
**方向が逆だった。** 浅さを疑ったのは、`bin/bookcheck` を書こうとして
「読者のクローンでも通るか」を考えたときである。**道具を作ろうとしたことが、先に自分を止めた。**

**測る前に「どちらへずれているはずか」を決めていた。** それが4件とも逆だったので、
そのまま押していれば**訂正のつもりで新しい誤りを4件公開していた。**

## 直したもの

1. **4件のコミット数を実測値へ訂正した**（104 / 139 / 147 / 110）
2. **各脚注を SHA に固定した。** 日付ではなく `d41f952` のような commit を書き、
   `git rev-list --count <SHA>` という**再現コマンドを併記した。**
   日付は範囲を持つが、SHA は1点である。**検算を勧めるなら、検算できる形で書く**
3. **浅いクローンでは少なく出ることを、脚注の中で読者に断った。**
   これは本書の主題（計器は黙って嘘をつく）そのものの実例でもある
4. **第6章・第7章に欠けていた「いつ時点の数値か」の断り書きを足した。**
   00〜05 は全章持っていた。**規約が2章だけ守られていなかった**

## この回が作った欠陥を1件、書いた直後に見つけた（`+` の根拠には数えない。09-08 の条項）

`bookcheck` の初版は、二重引用符の中にバッククォートで `` `git fetch --unshallow` `` と書いていた。
**bash のコマンド置換である。浅い回に、検査が実際に fetch を走らせていた。**
**検査した瞬間に、測っている対象が変わる。** 単引用符に直し、
「検査が git fetch を実行しないこと」を selftest に固定した。

## 旧 LP の URL は、消えている（前の回の宿題 / 次の一手1）

3つの計器が揃った。`Artifact action:read` → `not found`、`action:list`（scope:all）→ 新 URL 1件のみ。
**外に古い数字のページが2枚ある状態ではない。**

**そして `curl` は、この判定に使えない。** 存在しない UUID（`00000000-...`）でも
